## [0.3.0] - 2026-07-25

### Добавлено

- **Lock‑free пропускной список (skip list)** вместо B‑дерева в MemTable:
  - Чтение полностью без блокировок, запись использует CAS с EBR (Epoch‑Based Reclamation)
  - `Get()`: 0 аллокаций, пропускная способность выросла на **+159%** (7.1M → 18.4M оп/с)
  - `Put()`: аллокации сокращены с 5 до 1 на операцию, пропускная способность **+94%** (1.51M → 2.92M оп/с)

- **Zero‑copy VLog (`VLogView`)** с подсчётом ссылок:
  - `ReadView()` возвращает срез, указывающий непосредственно на mmap, без копирования данных
  - `Release()` уменьшает счётчик ссылок; `Close()` ожидает освобождения всех представлений
  - Чтение больших значений (4 КБ) улучшено на **+487%** (213K → 1.25M оп/с), аллокации сокращены с 8 до 0

- **Двухбуферный WAL** с переключением буферов без блокировок:
  - Задержка снижена с 580 нс до **170 нс** (в 3.4 раза быстрее)
  - Пропускная способность увеличена до **22M записей/с** (в 1.6 раза быстрее предыдущего Group Commit)

- **Адаптивный фильтр Блума** с оптимальным размером и числом хеш‑функций:
  - Основан на ожидаемом количестве ключей (n) и целевой вероятности ложноположительного срабатывания (1%)
  - Для 1000 ключей: память 8 КБ → 1.2 КБ, FPR 93% → 1.14%
  - Использует двойное хеширование по методу Кирша‑Митценмахера, ноль аллокаций в горячем пути

- **Бинарный поиск в индексе SSTable** (O(log N) вместо O(N)):
  - Заменяет линейное сканирование на `sort.Search`
  - Значительно ускоряет поиск для больших SSTable

- **Итератор слияния на куче (heap‑based merge iterator)** для потокового сканирования:
  - Больше не загружает все данные в память заранее
  - Сканирование: 4809 нс → 796 нс (**-83%**), аллокации 107 → 7 (**-93%**)

- **MVCCIterator** – декоратор для фильтрации удалённых записей (tombstone) при сканировании

- **Корректное завершение работы (Graceful Shutdown)** для всех фоновых задач (syncLoop, compaction, VLog)

- **Тесты на восстановление после сбоев (crash‑recovery)**: 6 сценариев (усечённый WAL, повреждение манифеста, сбой flush/compaction)

- **sync.Pool** для `WalEntry`, `heapItem`, `encodeBuffer`, блоков SSTable – сокращение аллокаций на 35–43%

- **EBR (Epoch‑Based Reclamation)** для безопасного освобождения памяти без участия GC

- **Поддержка mmap** для SSTable (Linux, macOS, Windows) с fallback

- **CRC32‑контрольные суммы** для блоков SSTable – проверка целостности данных

- **Диагностические и стресс‑тесты**

### Изменено

- **Group Commit** теперь включён по умолчанию (производительность улучшена без изменения API)
- Переход с `google/btree` на внутренний lock‑free пропускной список
- Все методы `Close()` теперь возвращают ошибки (обрабатываются через `internal/errors`)
- Реорганизация пакетов: `memtable` перенесён в `internal/engine/memtable/`
- Унифицировано сравнение ключей через `keys.CompareKeys`
- Структурированное логирование с уровнями (debug, info, warn, error)
- Удалены `fmt.Printf` из горячего пути – теперь используется только логгер

### Исправлено

- **SIGBUS** в VLog – исправлен порядок записи во избежание обращения к освобождённой памяти
- **Гонка** в WAL Close – теперь ожидается завершение `syncLoop`
- **Обработка tombstone в MVCC** – `GetLatest` теперь возвращает более старые неудалённые версии, если новейшая версия является tombstone
- **Обработка пустых значений** – различается отсутствие ключа (`nil`) и существующий ключ с пустым значением (`[]byte{}`)
- **Итератор SSTable** – теперь корректно работает с tombstone и бинарным поиском
- **Гонки в EpochManager** – замена `sync.Map` на `map + RWMutex`, устранены аллокации в горячем пути
- **Гонки** в логгере (`atomic.Int32`) и многих других компонентах
- **Все предупреждения линтеров** – комментарии к пакетам, неиспользуемый код, предупреждения staticcheck

### Удалено

- `TECHDEBT.md` (оставлен локально, в репозиторий не коммитится)
- Неиспользуемые модули: `notify`, `websocket` (заменены на gRPC)
- Дублирующий `WriteBatch` (`internal/engine/batch.go` – используется `txn/batch.go`)
- Неиспользуемые функции: `maybeCompactLevel0`, `maybeFlush` и другие
