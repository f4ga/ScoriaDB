## 📖 Что такое ScoriaDB?

**ScoriaDB** — встраиваемый LSM-движок хранения данных, написанный на чистом Go.

Это **один бинарник без внешних зависимостей**, который можно:
- Встраивать напрямую в Go-приложение через `go get`
- Запускать как отдельный gRPC-сервер с клиентами на 13+ языках
- Использовать через REST API или CLI

**Одной строкой:** *Чистая Go LSM-база с ACID, MVCC, Column Families и 18.4M чтений/с на ноутбуке.*

## 👤 Кому это нужно?

| Вы... | Зачем вам ScoriaDB |
|-------|---------------------|
| **Go-бэкенд разработчик** | Встроить быструю ACID-совместимую БД в свой сервис через `go get` |
| **Платформенный инженер** | Построить слой хранения без внешних зависимостей и cgo |
| **Основатель стартапа** | Запустить продукт со встроенной БД — без операционных затрат |
| **Студент** | Изучить устройство современной LSM-базы на чистом Go |

**Проблема, которую решает ScoriaDB:**

В Go есть встраиваемые БД, но у каждой есть существенные недостатки:

| База данных | Проблема |
|-------------|----------|
| **RocksDB** | C++ — требует cgo и C++ toolchain |
| **BadgerDB** | Медленная на маленьких значениях, страдает от L0-залипаний |
| **Pebble** | Нет ACID-транзакций, нет MVCC |
| **BoltDB** | Глобальный мьютекс, медленная запись |
| **LMDB** | C-библиотека, сложна для встраивания в Go |
| **LevelDB** | Нет ACID, нет MVCC, C++ |

**ScoriaDB решает все эти проблемы в одной чистой Go-библиотеке.**

## 🚀 Быстрый старт

### Установка

```bash
go get github.com/f4ga/ScoriaDB/pkg/scoria
```

### Встраивание в Go (1 минута)

```go
package main

import (
    "fmt"
    "log"
    "github.com/f4ga/ScoriaDB/pkg/scoria"
)

func main() {
    db, err := scoria.NewScoriaDB("./data")
    if err != nil {
        log.Fatal(err)
    }
    defer db.Close()

    db.Put([]byte("hello"), []byte("world"))
    value, _ := db.Get([]byte("hello"))
    fmt.Printf("%s\n", value)
}
```

### Запуск как сервер

```bash
go build -o scoria-server ./cmd/server
./scoria-server

# CLI
./scoria-cli set hello world
./scoria-cli get hello
./scoria-cli scan
```

## 📊 Производительность

**Тестовое окружение:** Intel Core i3-1215U (ноутбук, 8 потоков), 16GB DDR4, NVMe SSD, Go 1.23+, Linux.

*Эти бенчмарки воспроизводимы — запустите их сами:*

### 1. MemTable — In-Memory слой

Сюда сначала попадают все записи. ScoriaDB использует **lock‑free skip list** с **аренным аллокатором** — без мьютексов и без аллокаций в горячем пути.

| Бенчмарк | ops/s | ns/op | B/op | allocs/op | Ядер |
|----------|-------|-------|------|-----------|------|
| **Get** | **18.4M** | **72** | 23 | 1 | 8 |
| **Get** | 4.56M | 267 | 23 | 1 | 1 |
| **Get (последовательный)** | 4.58M | 264 | 23 | 1 | 8 |
| **Put** | **2.92M** | **432** | 23 | 1 | 8 |
| **Put** | 2.66M | 473 | 23 | 1 | 1 |
| **Put (последовательный)** | 2.71M | 469 | 23 | 1 | 8 |

**Что это значит:** In-memory слой ScoriaDB быстрее большинства персистентных БД на серверном железе — при работе на ноутбуке. 1 alloc/op означает минимальное давление на GC.

- Чистый Go (без cgo, кросс-компиляция куда угодно)

- Мультиязычные клиенты из коробки

**Ни одна другая БД в Go-экосистеме не предлагает этого сочетания.**

## 🧩 Возможности

### 1. ACID-транзакции

ScoriaDB предоставляет **ACID** (атомарность, согласованность, изоляция, долговечность) с **изоляцией снимков**:

- **Атомарность:** WriteBatch группирует операции — либо все, либо ничего
- **Согласованность:** MVCC гарантирует, что читатели видят консистентный снимок
- **Изоляция:** Изоляция снимков — писатели никогда не блокируют читателей
- **Долговечность:** WAL с fsync, Group Commit для производительности

```go
tx := db.NewTransaction()
defer tx.Rollback()

val, _ := tx.Get([]byte("balance"))
tx.Put([]byte("balance"), newBalance)

if err := tx.Commit(); err == scoria.ErrConflict {
    // повторить транзакцию
}
```

### 2. MVCC (Multi-Version Concurrency Control)

ScoriaDB использует **инвертированные временные метки** для MVCC:

- Каждый `Put` создаёт новую версию с уникальным commitTS
- Чтения используют `snapshotTS` для получения консистентного состояния на момент времени
- Писатели никогда не блокируют читателей — нет блокировок на чтение

**Детали реализации:** Ключи хранятся как `[user_key][^commitTS]`. Поскольку `^commitTS` уменьшается при увеличении `commitTS`, самая новая версия появляется первой при итерации. Это делает диапазонные сканы эффективными и упрощает компакцию.

### 3. Column Families (CF)

Column Families — это независимые LSM-деревья внутри одной базы данных:

- Каждая CF имеет свою MemTable, SSTable и компакцию
- Атомарные записи между CF через WriteBatch
- CF `__auth__` зарезервирована для аутентификации пользователей

```go
db.CreateCF("logs")
db.PutCF("logs", []byte("2025-01-01"), []byte("started"))
iter := db.ScanCF("logs", []byte("2025-"))
```

**Когда использовать:** Разные типы данных требуют разных настроек компакции или хранения (например, логи vs пользовательские данные vs кэш).

### 4. Lock‑free Skip List MemTable

MemTable использует **lock‑free skip list** с **аренным аллокатором**:

- **0 мьютексов** на запись — только CAS-операции
- **0 аллокаций в куче** в горячем пути — арена для узлов
- **18.4M чтений/с** и **2.92M записей/с** на ноутбуке
- **1 alloc/op** — дружественно к GC, стабильная задержка

**Детали реализации:** Skip list использует `atomic.Pointer` для указателей next и `//go:linkname fastrand` для lock‑free генерации случайной высоты. Удалённые узлы помечаются `deleted.Store(true)` и утилизируются через EBR (Epoch‑Based Reclamation).

### 5. Zero‑copy Value Log (VLog)

Большие значения (>64 байт) хранятся в отдельном Value Log с **mmap**:

- **Zero‑copy чтение:** Значения возвращаются как срезы, указывающие напрямую на память mmap
- **Подсчёт ссылок:** `VLogView` с `IncRef`/`DecRef` обеспечивает безопасное освобождение памяти
- **Долговечность:** CRC32-контрольные суммы и mmap с `MAP_SHARED` гарантируют консистентность
- **SIGBUS‑безопасность:** Путь записи пересчитывает указатель mmap после расширения

**Детали реализации:** `VLogImpl.Write()` читает `v.writeData` **после** `extendMmap()`, чтобы предотвратить использование освобождённой памяти. Это было исправлением для SIGBUS в v0.3.0.

### 6. WAL с Group Commit

Write‑Ahead Log использует **Group Commit** для группировки вызовов fsync:

- **Интервал по умолчанию 10 мс** — буферизированная запись с периодическим fsync
- **11.6M записей WAL/с** с 0 аллокаций
- **Долговечность:** fsync после каждого батча (или периодически для производительности)
- **Настраиваемость:** `WALOptions.GroupCommitInterval` и `GroupCommitEnabled`

**Сравнение:**

| Режим | Задержка | Пропускная способность |
|-------|----------|------------------------|
| Sync (fsync на каждую операцию) | 365 ns | 2.74M ops/s |
| **Group Commit (10ms)** | **115 ns** | **11.6M ops/s** |

### 7. SSTable с Bloom-фильтром

SSTable — это персистентный слой хранения:

- **Блочный индекс** для O(log N) поиска
- **Bloom-фильтр** для пропуска файлов без ключа (0 аллокаций)
- **Префиксное сжатие** для уменьшения размера хранилища
- **Уровневая компакция** для управления write amplification
- **Блочный пул** (`sync.Pool`) для переиспользования буферов при чтении

**Детали реализации:** `SSTableIterator` построен на куче и поддерживает эффективные префиксные сканы с MVCC-фильтрацией.

### 8. gRPC, REST, CLI

ScoriaDB — это не только встраиваемая библиотека, но и полноценный сервер БД:

- **gRPC:** Клиенты на 13+ языках (Python, Java, C++ и др.)
- **REST:** HTTP-эндпоинты с JSON
- **CLI:** Интерактивная оболочка с историей, управлением Column Families, админ-командами
- **JWT-аутентификация:** Роли admin/readwrite/readonly

**Команды CLI:**

```bash
./scoria-cli set hello world
./scoria-cli get hello
./scoria-cli scan --cf logs
./scoria-cli admin user-add john mypass --roles readwrite
```

### 9. Сборка мусора (GC)

Value Log — **append‑only** — старые данные никогда не перезаписываются. GC освобождает пространство:

- **Сбор живых указателей:** Сканирует LSM-дерево для поиска живых значений
- **Копирование в новый файл:** Копирует живые значения в новый VLog-файл
- **Атомарная замена:** Переключается на новый файл, удаляет старый
- **Ручной запуск:** Команда `admin gc` (автоматическая инкрементальная GC запланирована на v0.4.0)

**Детали реализации:** GC использует `readDirectLocked` для чтения значений без рекурсивной блокировки (исправлено в v0.3.0).
