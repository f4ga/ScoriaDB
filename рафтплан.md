## Этап 3: Рост (недели 9-14)

**Цель:** Оптимизировать Raft-кластер: ускорить чтение, добавить устойчивость к partition.

### Задачи

| ID | Задача | Описание | Оценка | Входные данные |
|----|--------|----------|--------|----------------|
| **RAFT-015** | Snapshot Raft-лога | Raft-лог растёт бесконечно. Добавляем snapshot: периодически сохраняем состояние LSM-движка и обрезаем лог до snapshot_index. | 1 неделя | RAFT-014 |
| **RAFT-016** | Восстановление из snapshot | При старте ноды: если raft.log пустой → загружаем последний snapshot. | 3 дня | RAFT-015 |
| **RAFT-017** | Lease на лидерство | Лидер получает lease (например, 5 секунд). Чтение с лидера без Raft (быстро). | 1 неделя | RAFT-016 |
| **RAFT-018** | Follower read | Клиент может читать с фолловера (если знает его). Фолловер проверяет lease лидера и отвечает. | 1 неделя | RAFT-017 |
| **RAFT-019** | Network partition: меньшинство read-only | При partition: ноды в меньшинстве переходят в read-only. Записи возвращают ошибку `ErrNotEnoughQuorum`. | 1 неделя | RAFT-018 |
| **RAFT-020** | Network partition: восстановление | При восстановлении сети: фолловеры догоняют отставание по Raft-логу. | 1 неделя | RAFT-019 |
| **RAFT-021** | Тест: network partition | Используем `iptables` или `tc` для эмуляции partition. Проверяем read-only и восстановление. | 1 неделя | RAFT-020 |

**Итог этапа 3:**
- ✅ Raft-лог не растёт бесконечно (snapshot каждые 10,000 записей или 64MB)
- ✅ Чтение с лидера без RTT (lease)
- ✅ Чтение с фолловеров (распределяем нагрузку)
- ✅ Network partition: меньшинство → read-only, большинство → работает
- ✅ После восстановления сети — догонка лога

**Проверка:**
```bash
# Чтение с лидера (быстро)
./scoria-cli get user:1 --consistency=LOCAL # 24.6 нс

# Чтение с фолловера (чуть медленнее, но без нагрузки на лидера)
./scoria-cli get user:1 --follower=node-2

# Network partition: изолируем node-3
tc qdisc add dev eth0 root netem loss 100%

# node-3 → read-only (записи падают)
./scoria-cli set user:2 "Bob" --node=node-3 # ErrNotEnoughQuorum

# Восстанавливаем сеть
tc qdisc del dev eth0 root

# node-3 догоняет лог → снова работает
./scoria-cli set user:2 "Bob" --node=node-3 # OK
```

## Этап 5: Вспашка нового поля (недели 21-28)

**Цель:** Распределённые транзакции поверх Raft. Snapshot Isolation с HLC и 2PC.

### Задачи

| ID | Задача | Описание | Оценка | Входные данные |
|----|--------|----------|--------|----------------|
| **TXN-001** | HLC (Hybrid Logical Clocks) | Реализация HLC: `timestamp = max(physical, logical + 1)`. Замена TSO. | 2 недели | RAFT-030 |
| **TXN-002** | HLC синхронизация | При каждом Raft-запросе обмениваемся HLC-таймстемпами. Держим часы синхронизированными. | 1 неделя | TXN-001 |
| **TXN-003** | Snapshot Isolation на кластере | Транзакция получает startTS = HLC.now(). Все чтения — на этот снапшот. | 1 неделя | TXN-002 |
| **TXN-004** | 2PC Phase 1: Prewrite | Координатор → все регионы: "prepare keyX с commitTS". Регионы проверяют конфликты. | 2 недели | TXN-003 |
| **TXN-005** | 2PC Phase 2: Commit | Координатор → все регионы: "commit keyX". Регионы применяют через Raft. | 1 неделя | TXN-004 |
| **TXN-006** | Conflict detection | Write-write: если ключ был изменён между startTS и commitTS → конфликт. Read-write: если прочитанный ключ изменён → конфликт. | 2 недели | TXN-005 |
| **TXN-007** | Retry loop в клиенте | Клиент автоматически повторяет транзакцию при `ErrConflict`. | 1 неделя | TXN-006 |
| **TXN-008** | Локальные транзакции | Если все ключи в одном регионе → 2PC не нужен. Просто коммитим через Raft. | 1 неделя | TXN-007 |
| **TXN-009** | Таймауты транзакций | Если транзакция длится >5 секунд → автоматический rollback. | 3 дня | TXN-008 |
| **TXN-010** | Тесты транзакций | 10+ сценариев: конфликты, локальные/распределённые транзакции, таймауты. | 1 неделя | TXN-009 |

**Итог этапа 5:**
- ✅ HLC работает вместо TSO (нет единой точки отказа)
- ✅ Snapshot Isolation на кластере
- ✅ 2PC для распределённых транзакций
- ✅ Локальные транзакции без 2PC (в 3× быстрее)
- ✅ Retry loop + таймауты

**Проверка:**
```go
// Транзакция через 2 региона
tx := db.NewTransaction()
tx.Put("user:1", "Alice")   // регион 1
tx.Put("order:1", "100")    // регион 2
tx.Commit() // 2PC, 3 RTT

// Локальная транзакция (1 регион)
tx2 := db.NewTransaction()
tx2.Put("user:1", "Alice")   // регион 1
tx2.Put("user:2", "Bob")     // тоже регион 1
tx2.Commit() // локальный commit, 1 RTT
```
